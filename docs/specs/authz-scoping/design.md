# 유저별 고객사 접근 범위 (AuthZ) — 설계 (2026-10-20)

상태: **진행 중**. 권한 표와 세부 결정 1~3은 2026-10-20 사용자 승인(추천안).

## 왜

로그인(Google SSO)은 2026-06에 붙었지만, 로그인한 사람은 **누구나 모든 고객사의 데이터를 본다**. 허용 도메인
(`mz.co.kr`, `megazone.com`)이면 누구나 로그인할 수 있고, 실제로 일반 사용자 2명(koo, sxt)이 쓰고 있다. 화면의
"담당 고객사"는 개인 화면 필터일 뿐 접근 제어가 아니다(`preferences.py` 문서에 그렇게 적혀 있다). 백엔드가 보안
경계다 — 프론트 필터로는 막을 수 없다.

## 규칙

- 고객사에 `managers: [email]`(소문자)를 둔다.
- **관리자**(`ADMIN_EMAILS`)는 전부 본다. **일반 사용자**는 `managers`에 자기 이메일이 든 고객사만 본다.
- `ADMIN_EMAILS`가 비어 있거나 인증이 꺼진 환경(이메일 없음)은 **제한 없음** — 로컬/미구성 환경 동작을 유지한다
  (`admin_enforced()`와 같은 기준).

| 동작 | 일반 사용자 | 관리자 |
|---|---|---|
| 고객사 목록·상세 | 담당 고객사만 | 전체 |
| 그 고객사의 계정·리소스·알람·알림 이벤트·인시던트 조회 | 담당 고객사 것만 | 전체 |
| 모니터링 켜기/끄기, 알람 설정, 동기화 | 담당 고객사 것만 | 전체 |
| 고객사 생성 | 가능 — 만든 사람이 자동 담당자 | 가능 |
| 고객사 편집(담당자 지정 포함) | 담당 고객사만 | 전체 |
| 계정 등록·연결 테스트·리전 변경 | 담당 고객사만 | 전체 |
| 고객사·계정 **삭제** | 불가 | 가능 |
| 고객사가 없는 데이터(중앙 계정 자체 리소스 등) | 안 보임 | 전체 |
| 전역 설정(알림 정책, 전역 채널·사일런스, 버스 재정합) | 기존 그대로(관리자 전용) | 가능 |

## 데이터가 고객사에 닿는 길

| 데이터 | 연결 |
|---|---|
| 고객사, 계정, 인시던트, 알림 이벤트, 채널, 사일런스, 임계치 오버라이드 | `customer_id`를 직접 가진다 |
| 인벤토리 리소스 행 | `customer_id`(없으면 고객사 없음) |
| 인벤토리 알람 행 | `customer_id` 없음 → `account_id` → 계정 테이블의 `customer_id` |
| 실행 기록(monitor-runs) | `account_id` → 계정 |
| 작업(jobs) | 만들 때 대상의 (고객사, 계정)을 `owners`로 기록 → 조회 시 **모두** 범위 안이어야 보인다. 기록 없는 작업(예전 작업·전체 동기화)은 관리자만 |

같은 AWS 계정이 두 고객사에 걸릴 수 있다(계정 테이블 키가 `customer_id + account_id`). 그래서 계정은 "접근 가능한
고객사 중 하나에 걸려 있으면 접근 가능"으로 본다.

## 구현

- `api_handler/authz.py`: `scope_for(event) -> Scope`. `Scope`는 `unrestricted`, `customer_ids`,
  `account_ids`(계정 테이블에서 파생)를 가지고 `allows_customer(cid)`, `allows_account(aid)`, `allows_item(item)`을 제공한다.
  요청마다 고객사·계정 테이블을 한 번씩 읽는다(현재 각 2행·소수 — 규모가 커지면 캐시).
- 조회 라우트는 결과를 범위로 걸러내고, 단건·변경 라우트는 대상이 범위 밖이면 **404**를 낸다(존재 여부를 흘리지 않는다).
  삭제는 관리자가 아니면 403.
- 고객사 생성은 `managers=[생성자]`. 새 `PUT /customers/{id}`로 이름·담당자를 편집한다(담당자 비우기는 막는다 — 고아 고객사 방지).
- 이전: `scripts/migrate_customer_managers.py` — 사용자 설정의 `owned_customer_ids`를 고객사 `managers`로 옮긴다. 먼저 드라이런.
- 프론트: 고객사 편집에 담당자 지정. "담당" 체크박스와 개인 필터(`useOwnedCustomers`)는 권한으로 대체됐으므로 정리한다.

## 열린 질문

- 사용자 목록이 없어서 담당자는 이메일을 직접 입력한다.
