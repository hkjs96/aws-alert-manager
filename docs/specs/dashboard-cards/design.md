# 대시보드 카드 · 채널 조건 화면 — 디자인 초안 (2026-10-20)

상태: **초안, 검토 대기**.

## 1. 대시보드 카드

### 지금 문제
- 카드를 눌러도 아무 데도 가지 않는다.
- "Active Alarms"가 **우리가 만든 알람만** 센다. HOME 실측: ALARM 상태 2개(`TEST-ALARM`, WEBFIL NetworkIn)가 모두
  고객이 만든 알람이라 카드에 0, "All clear"가 뜬다.
- "Unmonitored 296 · Action needed"는 고객이 고른 리소스만 감시하는 운영 방식에서 경고가 아니다.
- "All connected"는 고정 문구, "−1 from last visit"은 필터가 바뀌어서 생긴 착시다.

### 초안
```
┌ 감시 중 ─────────┐ ┌ 알람 발생 ─────────┐ ┌ 감시 안 함 ───────┐ ┌ 계정 ─────────────┐
│ 4                │ │ 2                  │ │ 296              │ │ 1                │
│ 리소스 300개 중  │ │ 우리 0 · 고객 2    │ │ 켤 수 있는 리소스 │ │ 연결 1 · 실패 0  │
│ 리소스 보기 →    │ │ 알람 보기 →        │ │ 리소스 보기 →    │ │ 계정 관리 →      │
└──────────────────┘ └────────────────────┘ └──────────────────┘ └──────────────────┘
   회색                 0이면 초록, 있으면 빨강   회색(경고 아님)       실패가 있으면 빨강
```
- 카드 전체가 링크다.
  - 감시 중 → `/resources?monitoring=on`
  - 알람 발생 → `/alarms?state=ALARM`
  - 감시 안 함 → `/resources?monitoring=off`
  - 계정 → `/settings#accounts`
  - 현재 고객사·계정 필터를 주소에 실어 간다.
- "알람 발생"은 고객이 만든 알람도 센다. 출처를 나눠 보여 줘서, 우리가 만든 알람이 없는 고객사도 상황을 알 수 있게 한다.
  고객 알람은 인벤토리에 이미 수집되므로 집계만 바꾸면 된다(백엔드 → stg → promote).
- "지난 방문 대비"는 필터가 걸려 있으면 숨긴다. 같은 범위끼리만 비교한다.

```

        ☐ SEV-4  성능 저하 · 4시간 내
        ☐ SEV-5  참고 · 다음 업무 시간

 리소스 타입  (●) 전부 받기   ( ) 골라서 받기
              └ 고르면: 이 고객사에 있는 타입만 — EC2 12 · ALB 3 · RDS 2 …  [모든 타입 보기]

 계정         (계정이 하나뿐이면 이 줄을 숨긴다)

 ─────────────────────────────────────────────
 HOME의 SEV-1~3 알림을 모든 리소스에서 받습니다.
```

- 등급은 버튼과 설명을 한 줄로 합친다. 따로 두면 눈으로 짝을 지어야 한다.
- 아무것도 고르지 않으면 전부 받는다는 규칙을 숨기지 않고, "전부 받기 / 골라서 받기"를 직접 고르게 한다.
- 채널 목록에 **[테스트 보내기]** 버튼을 둔다(3단계, 백엔드).
